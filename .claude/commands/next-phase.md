현재 단계를 완료 처리하고 다음 단계 준비를 해줘.

## 절차

### 1. 현재 단계 검증 결과 확인
- `docs/specs/PHASE_{현재단계}-verify.md` 파일이 존재하는지 확인
- 종합 판정이 ✅인지 확인
- ❌이면 "검증을 먼저 통과해야 합니다" 출력 후 중단
- verify 리포트의 "Codex 코드리뷰 결과" 섹션이 "미실시"이면 경고 출력: "Codex 코드리뷰가 미실시입니다. 리뷰 없이 진행하시겠습니까?"

### 2. STATUS.md 업데이트 — 현재 단계
- 현재 단계 상태를 "✅ 완료"로
- 완료일을 오늘 날짜로 기록

### 3. 다음 단계 결정 — 분기 처리

#### 3-A. Phase 0 → 디자인 시스템 추출 (특수 케이스)
현재 단계가 0이고, `docs/REF_디자인_시스템.md`가 **없으면**:

→ "디자인 시스템 추출" 단계로 전환:
- STATUS.md의 "디자인 시스템 추출" 섹션 상태를 🔵 진행중으로
- 시작일을 오늘 날짜로 기록
- "현재 단계" 값은 변경하지 않음 (여전히 0 — 코드 단계 기준)
- 사용자에게 다음 안내 출력:

```
✅ Phase 0 완료.

다음은 [디자인 시스템 추출] 단계입니다 (비-코드 작업).

수동 작업:
1. Claude Design으로 핵심 화면 시안 1~2개 생성
   - 예: 대시보드, 발주서 공급처 배정 화면
2. 시안에서 다음 값 추출:
   - 색상 토큰 (Primary, Status, Gray 10단계, Surface)
   - 타이포 스케일 (h1~h3, body, caption)
   - 스페이싱 체계
   - 라운딩, 그림자
   - 컴포넌트별 className (Button, Input, Card, Badge, Modal, Table 등)
3. docs/REF_디자인_시스템.md 작성
4. src/index.css의 @theme 블록을 추출한 정식 토큰으로 교체
5. npm run build 통과 확인

완료되면 다시 /project:next-phase 실행하세요 — Phase 1으로 전환됩니다.
```

→ 종료. (Phase 1 브리핑 안 함)

#### 3-B. Phase 0 + 디자인 시스템 추출 완료 → Phase 1
현재 단계가 0이고, `docs/REF_디자인_시스템.md`가 **존재하면**:

→ 디자인 시스템 추출 완료 처리:
- STATUS.md의 "디자인 시스템 추출" 섹션 상태를 ✅ 완료로
- 완료일을 오늘 날짜로 기록
- 추출 결과 산출물 체크리스트 모두 [x]로 표시

→ Phase 1로 전환 (3-C 절차 동일하게 수행)

#### 3-C. 일반적인 다음 단계 전환 (Phase 1 이후)
- 다음 단계 번호로 STATUS.md "현재 단계" 값 갱신
- 다음 단계 상태를 🔵 진행중으로
- 시작일을 오늘 날짜로 기록

### 4. 다음 단계 스펙 존재 확인
- `docs/specs/PHASE_{다음단계}_*.md` 파일이 존재하는지 확인
- 없으면 "다음 단계 스펙 문서가 아직 작성되지 않았습니다. 스펙 작성을 요청하세요." 출력 후 종료

### 5. 다음 단계 브리핑
스펙이 있으면:
- 다음 단계 이름 + 핵심 내용 요약 (5줄 이내)
- 새로 생성/수정할 파일 목록 (스펙의 "작업 목록" 기준)
- 주의사항 (이전 단계와 달라지는 점, 새로 적용할 규칙)
- 참조해야 할 폴더별 CLAUDE.md 목록
- 관련 REF 문서 목록

[위에 명시한 안내 텍스트]

완료 후 다시 /project:next-phase 실행 → Phase 1 시작

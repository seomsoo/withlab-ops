현재 단계 스펙 문서를 읽고 Vitest 테스트 케이스를 생성해줘.

## 절차

### 1. 스펙 분석
- `docs/STATUS.md`에서 현재 단계 확인
- 해당 스펙 문서의 비즈니스 규칙, 엣지케이스, 검증 항목 추출

### 2. 테스트 대상 판별
테스트 작성 대상 (핵심 로직만):
- `src/lib/parsers/*.ts` — 파서 함수
- `src/lib/matching/*.ts` — 매칭 엔진
- `src/lib/generators/*.ts` — 엑셀 생성 로직
- `src/utils/phone.ts` — 전화번호 포맷
- 자동 배정 로직, 수량 분배 로직

테스트 제외:
- UI 컴포넌트
- Supabase API 호출 (모킹 필요 → 비용 대비 효과 낮음)
- E2E 테스트

### 3. 테스트 케이스 생성
각 함수에 대해:
- **정상 케이스**: 기본 입력 → 기대 출력
- **엣지케이스**: 스펙에 명시된 특수 상황 (빈 값, 0, 중복, 특수문자 등)
- **에러 케이스**: 잘못된 입력 → invalidRow 또는 에러

### 4. 파일 생성
- 테스트 파일을 원본 파일 옆에 `*.test.ts`로 생성
- 기존 테스트 파일이 있으면 누락된 케이스만 추가

## 테스트 작성 규칙
```ts
// Vitest + describe/it 패턴
import { describe, it, expect } from 'vitest'

describe('함수명', () => {
  it('정상: 설명', () => {
    // given → when → then
  })

  it('엣지: 설명', () => {
    // ...
  })

  it('에러: 설명', () => {
    // ...
  })
})
```

## 출력
- 생성된 테스트 파일 목록
- 각 파일의 테스트 케이스 수
- `npm run test -- --run` 실행 결과

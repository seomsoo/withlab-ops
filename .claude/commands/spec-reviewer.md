스펙 문서와 실제 구현 코드를 줄 단위로 심층 비교해줘.

## 입력
- `docs/STATUS.md`에서 현재 단계 번호 확인
- 해당 단계의 `docs/specs/PHASE_{N}_*.md` 읽기
- 관련 REF 문서 (`docs/REF_*.md`) 읽기
- 해당 단계에서 생성/수정된 소스 파일 전부 읽기

## 비교 항목

### 데이터 흐름 검증
- 스펙에 명시된 데이터 흐름 (A → B → C)이 코드에서 실제로 그렇게 연결되어 있는가?
- 함수 호출 체인이 스펙의 흐름과 일치하는가?
- 중간에 데이터가 변환될 때 필드 누락이 없는가?

### 엣지케이스 검증
- 스펙에 명시된 엣지케이스 (빈 행, 수량 0, 중복 주문 등)가 코드에서 처리되는가?
- 에러 경로가 스펙의 invalidRow/unmatched 등 상태와 일치하는가?

### 비즈니스 규칙 검증
- 수량 분할 금지가 실제로 강제되는가? (DB unique 제약 + 코드 레벨 모두)
- 매칭키 규칙 (쿠팡=주문번호, 토스=주문상품번호)이 모든 경로에서 일관되는가?
- "오늘만 변경" vs "기본 매핑 변경" 분기가 올바른가?

### 타입 안전성 검증
- Zod 검증이 외부 데이터 경계에 빠짐없이 적용되었는가?
- DB snake_case ↔ TS camelCase 변환에서 필드 누락이 없는가?
- any 타입이나 타입 단언(as)이 불필요하게 사용된 곳이 있는가?

## 출력 형식

```
## spec-reviewer 심층 비교 결과

### 🔴 필수 수정 (스펙 위반)
- [파일:라인] 스펙 요구사항 vs 실제 구현 차이 설명 + 수정 방법

### 🟡 권장 수정 (개선사항)
- [파일:라인] 개선 사항 설명

### 🟢 양호
- 정상 확인된 주요 항목 나열

### 요약
필수 수정 N건 / 권장 수정 N건 / 양호 N건
```

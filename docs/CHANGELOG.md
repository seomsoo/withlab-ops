# 사용자 요청 및 변경 이력

사용자가 요청한 기능 추가·수정과 실제 반영 내용을 기록한다. 최신 날짜를 위에 추가하고, **요청 → 반영 내용 → 상태 → 확인 사항** 순서로 작성한다. 후속 작업은 완료 항목과 구분하며 구현·배포·검증 상태를 혼동하지 않는다.

## 2026-11-03 — 사용 가이드를 주제별 페이지로 개편

**요청:** 앱 사용 가이드가 읽기 어려우니 AI 티 나는 디자인을 빼고, 토스 느낌을 유지하면서 Notion 도움말 센터처럼 주제별 페이지로 나눠 정리. 따로 보낸 과일 사전 사용법 문서의 내용이 앱 가이드에 들어갔는지 확인.

**반영 내용**

- 한 페이지에 모여 있던 가이드를 16개 글로 나눈다. `/guide`는 묶음별 글 목록과 검색, `/guide/:slug`는 글 화면이다.
- 글 화면은 왼쪽 전체 글 목록, 가운데 본문, 오른쪽 "이 페이지" 목차, 아래 이전·다음 글로 구성한다.
- 접는 섹션, 그라데이션 배너, 제목 옆 아이콘 상자를 없앤다. 본문은 16px, 폭 700px 이하로 맞춘다.
- 글은 합니다체로 통일하고, 버튼 이름은 굵게 표시한다. 표는 여러 항목을 비교할 때만 쓴다.
- 과일 사전 사용법 문서에만 있던 내용을 앱 가이드와 `docs/USER_GUIDE.md`에 추가한다: 새 과일 추가 순서, 안 잡히는 표현 추가 순서, 공급처 상품명의 과일 이름도 키워드에 넣기, 같은 표현을 두 묶음에 넣으면 위쪽 묶음만 잡히는 점, 공급처에 있는 중량을 바꾸는 무게 변환 주의, 완전삭제 전 비활성 권장, [재배정] 주의, 상품명의 "로얄" 때문에 로얄과로 잡히는 경우.
- 16개 글을 화면 코드와 대조해 틀린 내용을 고친다. 앱 가이드와 `docs/USER_GUIDE.md`에 같이 반영한다.
  - 자동 배정 글: 없는 버튼 이름(상품명 분석·자동 매칭·학습)을 빼고, 실제 순서(품목 검토 선택 → 품목 매핑 → 상품 목록 비교 → 미분류)로 다시 쓴다.
  - [분배]는 공급처가 배정된 주문이 2건 이상인 행에만 보인다.
  - 공급처별 배정 삭제 후 주문은 미분류로 돌아간다("추천"으로 돌아간다는 설명 삭제).
  - 공급처 관리 목록에는 [상품 목록 갱신]이 없고 업로드 아이콘이 있다. 상품 파일을 올리는 세 곳을 적는다.
  - 공급처 복원 버튼 이름은 "활성화"다.
  - 공급처 파일의 열 순서가 바뀌면 [양식 재설정]으로 열을 다시 지정해야 한다는 안내를 추가한다.
  - 이미 배정된 작업건에서 품목 검토 선택은 [재배정]을 눌러야 반영된다는 안내를 추가한다.
  - 토스 엑셀은 헤더 위치가 바뀌어도 읽으므로, 읽지 못하는 경우를 시트 이름과 열 제목으로 좁힌다.
- 단순화했던 설명도 실제 동작대로 고친다.
  - 품목 매핑: 플랫폼 전용 매핑이 공통 매핑보다 먼저인 점, 옵션까지 같은 매핑이 먼저인 점, 상품명 비교 때 무시하는 글자, 우선순위가 쓰이는 경우, 상품 목록이 없을 때의 배정 규칙.
  - 품목 검토: "최다"는 상품명마다 가장 많이 보낸 곳이라는 점, [기본 저장]이 품목 이름으로 공통 매핑을 저장한다는 점.
  - [기본 매핑도 변경]은 이 플랫폼의 같은 상품·옵션 매핑에서 기본을 바꾸고, 매핑이 없으면 새로 만든다.
  - 주문 업로드 탭은 진행중 작업건에서 앞 단계로만 돌아갈 수 있다.
- 운영 화면(읽기 전용)에서 확인한 차이를 반영한다: 파일 행의 [교체]도 같은 선택 창을 띄우고, 업로드 화면 파일 목록에는 "쿠팡1" 같은 이름이 나오지 않는다.

**상태:** 구현 완료, `fix/allocation-and-guide` 브랜치에 푸시. main 병합·배포 전. 운영 화면은 대시보드, 작업건 목록, 주문 업로드까지만 보기로 확인했다. 실제 데이터라 버튼을 누르는 동작은 확인하지 않았다.

**확인 사항:** 사용법 문서의 "감귤 키워드에 서귀포·타이벡·타이백이 있다"는 주의와 "뺵스팜 3Kg" 예시는 지금 사전과 공급처에만 해당하는 내용이라 앱 가이드에는 일반 규칙으로만 넣었다. 화면 캡처는 아직 없다.

## 2026-11-02 — 자동 배정 동작 수정

**요청:** 안내서와 대조하다 발견한 동작 차이 중 건너뛰기, 비활성 공급처, 추가 주문을 코드로 수정.

**반영 내용**

- 품목 검토에서 [건너뛰기]를 누르거나 공급처를 하나도 고르지 않고 [배정 시작]을 눌러도 품목 매핑 기준으로 자동 배정을 실행한다.
- 비활성 공급처는 품목 매핑이 남아 있어도 자동 배정하지 않는다. 다른 활성 후보가 있으면 그쪽으로 배정하고, 없으면 미분류로 남긴다.
- [기존 주문에 추가]로 들어온 새 주문은 업로드 직후 자동 배정한다. 기존 배정, 수동 변경, 공급처별 삭제로 비운 주문은 건드리지 않는다.
- 아직 배정 전인 작업건은 추가 업로드 때 배정하지 않고 배정 단계에서 처리한다.
- [기본 저장]은 코드를 바꾸지 않고 다음 품목 검토의 추천 표시로 유지한다.
- 2026-11-03 Codex 리뷰 P2 반영: 공급처 상품 목록이 하나도 없을 때도 비활성 공급처 매핑을 먼저 빼고 고른다. 전에는 기본 매핑이 비활성이면 활성 후보가 있어도 미분류가 됐다.

**상태:** 코드 구현과 자동 테스트 완료, `fix/allocation-and-guide` 브랜치에 푸시. main 병합·배포 전. 브라우저 확인은 하지 않았다.

**확인 사항:** 비활성 공급처 포함은 `PHASE_04` 스펙에 명시된 의도적 정책이었고, 이번 변경은 그 정책을 바꾸는 것이다. 품목 매핑이 비활성 공급처뿐인 주문은 이제 미분류로 나온다.

## 2026-11-02 — 사용 안내서 현행화

**요청:** 초기 작성 후 크게 바뀌지 않은 사용 안내서를 지금 기능에 맞게 수정.

**반영 내용**

- 앱 안내서와 `docs/USER_GUIDE.md`를 함께 고친다.
- 공급처 배정: 가격 미확인 확인 방법, 목록 필터, 상품 목록 갱신, 재배정 주의를 추가하고 버튼 이름을 실제 화면에 맞춘다.
- 운송장 업로드: 주문번호 없는 운송장 경고를 설명한다.
- 과일 사전: 언제 쓰는지, 작동 방식, 키워드 규칙, 적용 시점을 추가한다. 틀린 예시(`3kg → 5kg`, 한 글자 동의어)를 고친다.
- ‘사전 없이도 40여 종 자동 인식’을 고친다. 품목 검토의 묶음에만 해당하고 공급처 상품 자동 선택에는 사전이 필요하다.
- 공급처·과일 사전의 비활성화 방법을 실제 아이콘에 맞춘다.
- 자주 묻는 질문에 가격 미확인과 플랫폼 파일 누락 주문을 추가한다.
- 코드와 전체 대조해 버튼·메뉴 이름, 단계, 동작을 고친다. 품목 매핑 우선순위(숫자가 작을수록 우선), 상품명 변환의 빈 옵션, 택배사 매핑(공급처 구분 없음), 양식 메뉴 위치가 주요 수정이다.
- 추천 처리, 상품 목록 전체 교체, 공급처별 운송장 양식, 가격정리 패널, 운송장 재업로드 대체, 운송장 건너뛰기, 미매핑 품목 감지, 대시보드 안내를 추가한다.

**상태:** 문서와 앱 안내서 수정, 커밋·배포 전. 문구는 코드로 대조했고 앱 화면과 한 줄씩 비교하지는 않았다.

**확인 사항:** 쿠팡 운송장 양식의 매칭키 열은 코드로 확정되지 않아 ‘묶음배송번호 관련 열’로 적었다. 화면 문구 중 ‘모든 다운로드를 마치면 완료 상태로 변경’과 매칭 결과의 택배사 매핑 링크는 실제와 달라 별도 수정이 필요하다.

## 2026-11-02 — 운송장 파일 순서 맞춤 및 가격정리 붙여넣기

**요청:** 가격정리의 택배사·운송장번호를 채우려면 운송장 작업 결과가 필요한데, 플랫폼 파일과 순서가 달라 옮기기 어려움. 플랫폼 파일을 가격정리 순서로 맞추고, 운송장 3단계에서 바로 복사해 붙여 넣고, 미리보기도 있으면 좋겠음.

**반영 내용**

- 쿠팡·토스 다운로드 파일의 행 순서를 가격정리와 같게 맞춘다. 양식과 컬럼은 바꾸지 않는다.
- 운송장 3단계에 ‘가격정리에 운송장 붙여넣기’ 영역을 추가한다. 주문 목록별로 전체·운송장·빈칸 건수를 보여 준다.
- [복사]는 택배사와 운송장번호를 가격정리 순서로 복사한다. A3 칸에 붙여 넣으면 A열과 B열에 들어간다.
- 운송장이 없는 주문은 빈 줄로 복사해 아래 행이 밀리지 않게 한다.
- 택배사는 플랫폼 표기로 변환한다. 매핑이 없으면 공급처 표기로 나가고 미리보기에 ‘매핑 필요’로 표시한다.
- [미리보기]에서 가격정리 행 번호, 주문번호, 수령자, 상품, 택배사, 운송장번호를 확인한다.
- 운송장번호가 금액이나 `1.23E+11`처럼 표시되지 않도록 Excel 텍스트 서식을 함께 복사한다. 양식 B열이 `₩` 금액 서식이기 때문이다.
- 붙인 칸의 테두리가 사라지는 문제가 있어 복사 내용에 양식과 같은 테두리·글꼴·정렬을 넣는다. 크롬의 Clipboard API가 서식을 지울 수 있어 copy 이벤트 방식으로 복사한다.
- 공급처 운송장 업로드에서 주문번호 없이 운송장번호만 있는 행을 건너뛰면 건수와 안내를 표시한다.
- 공급처 파일의 값이 `=`, `+`, `-`, `@`로 시작하면 일반 텍스트 복사에서 수식으로 실행되지 않도록 앞에 `'`를 붙인다.
- 운송장이 없는 주문은 플랫폼 파일에도 들어가지 않으므로 건수를 경고로 표시한다.
- 운송장이 한 건도 없는 목록은 복사 버튼을 비활성화해 빈 값으로 덮어쓰는 일을 막는다.
- 가격정리 조회에 실패해도 플랫폼 파일 다운로드는 막지 않는다. 기존 순서로 내려받고 경고를 표시한다.
- 가격정리 파일 생성, A열 빈칸 출력, 가격정리 정렬은 바꾸지 않는다. 정렬을 바꾸면 이미 받은 파일과 행이 어긋나기 때문이다.
- 간편 운송장은 가격정리가 없어 제외한다.

**상태:** `main` 병합·운영 배포 완료(수식 차단 수정은 후속 배포 대상). 자동 테스트와 Codex 리뷰(지적사항 없음)를 통과했다. 맥용 Excel에서 복사, 테두리, 운송장번호 표시를 사용자가 확인했다. 쿠팡·토스 실제 업로드는 확인하지 않았다.

**확인 사항**

- 가격정리 파일을 정렬했거나 행을 지웠거나, 파일을 받은 뒤 주문을 추가했다면 행이 어긋날 수 있다. 시스템이 감지할 수 없어 화면에서 첫 주문번호와 마지막 주문번호를 확인하도록 안내한다.
- 붙여 넣으면 직접 입력한 칸도 덮어써지고, 운송장 없는 줄은 비워진다.
- 미매칭 경고는 올라온 운송장만 세므로, 운송장이 아예 없는 주문은 잡지 못한다. 위 건수 경고로만 확인할 수 있다.
- 주문번호 없는 운송장 경고는 업로드 직후 결과 화면에만 표시한다. 건수를 DB에 저장하지 않아 이전 업로드는 알 수 없다. 한 주문을 여러 박스로 나눈 정상 행도 함께 집계된다.
- 2026-10-30 오전 작업건의 쿠팡1 8건(`[1차완판] 고당도 제주감귤 / 1개 대과 10kg`, 뺵스팜)은 운송장이 없어 플랫폼 파일에 빠져 있다. 뺵스팜 송장 파일의 유효 행이 68행뿐이었고 매칭 오류는 아니다. 사용자 제외인지 공급처 미발송인지 확인이 필요하다.

## 2026-11-02 — 공급처 배정 과일 필터

**요청:** 공급처 배정에서 품목별로 거르려면 브라우저 찾기를 써야 해서 불편함. 사용자가 쓰기 쉽게 품목으로 필터링해서 보고 싶음.

**반영 내용**

- 공급처 배정 목록에 과일 선택 필터를 추가한다. 과일 사전으로 판정한 과일과 품목 수를 보여 준다.
- 사전에 없는 과일이나 두 과일이 섞인 상품은 ‘기타’로 묶는다.
- 상태·공급처 필터와 함께 적용한다.
- 가격 미확인 바로가기를 누르면 미확인 품목이 가려지지 않도록 과일 필터도 해제한다.

## 2026-11-02 — 감귤 공급처 상품 매칭 수정

**요청:** 감귤을 뺵스팜에 보내는데 공급처 배정에서 업체 상품명이 아닌 플랫폼 상품명이 나와 수동으로 작업 중. 뺵스팜 상품목록은 중량·크기 조합 6개뿐인데도 매칭이 잘 되지 않음.

**원인:** 2026-09-16에 과일 사전 `감` 카테고리가 키워드 `감`으로 추가되면서 ‘감귤’에 `감`과 `감귤`이 동시에 잡혔다. 카테고리가 둘 이상이면 과일을 판별하지 않는 규칙 때문에 공급처 상품을 찾지 못했고, 발주 상품명이 플랫폼 상품명으로 대체되며 단가도 비었다. 감홍사과(`감`+`사과`), 대봉감(`감`+`대봉감`)도 같은 구조로 충돌했다.

**반영 내용**

| 구분 | 변경 |
| --- | --- |
| 과일 판별 | 같은 글자에 겹친 키워드는 긴 쪽, 길이가 같으면 뒤쪽을 남김 (예: 햇감귤 → 감귤) |
| 등급·크기 | 판정된 과일의 사전에서만 찾음 |
| 옵션 우선 | 중량·크기는 상품명보다 옵션을 먼저 봄. `[S-M 로얄과]`처럼 대괄호 안의 크기도 읽음 |
| 동점 처리 | 공급처 상품 후보가 최고점 동점이면 임의로 고르지 않고 플랫폼 상품명과 빈 단가로 둠. 가격 미확인으로 잡혀 작업자가 직접 선택 |
| 감귤 기본 크기 | 주문에 크기가 없으면 대과로 판단 (크기가 없는 주문 6,097건 중 작업자 선택 6,043건이 대과) |
| 운영 과일 사전 `감` | 키워드 `감` 삭제. `햇감`, `단감` 유지. 카테고리는 유지 |
| 운영 과일 사전 `감귤` | 크기 표현 `중대`, `혼합`, `m-l`, `l-2l`, `2l-l`, `로열`, `꼬마` 추가. 중량 변환 `2kg → 3kg`, `2.5kg → 3kg` 추가 |

**상태:** 운영 과일 사전 변경 완료, 코드 `main` 병합 완료. Codex 리뷰 P1 없음. 브라우저 화면과 실제 주문 결과는 아직 확인하지 않았다.

**검증 결과(운영 데이터로 재현, 실제 주문 처리 결과 아님):** 과일 인식은 전체 12,618건 중 4,628건에서 12,524건으로 늘었다. 최근 3주 귤 221종은 품목 검토에서 뺵스팜을 지정하면 모두 상품명과 단가가 들어간다(수정 전 0종). 작업자가 선택한 상품과 중량·크기가 일치하는 비율은 7,279건 중 7,245건(99.5%)이다. 현재 공급처 상품목록에 있는 상품으로 저장된 10,575건을 수정 전후로 비교하면 저장값과 같은 상품을 고른 수가 2,852건에서 10,490건으로 늘었고, 맞던 주문이 틀어진 경우는 없었다. 나머지 85건 중 71건은 단가 없음으로 표시되고 14건은 다른 상품이 선택된다.

**확인 사항**

- 품목 검토 없이 자동 배정하면 귤 221종 중 154종은 추천 상태로 남는다.
- 위 14건처럼 저장값과 다른 상품이 선택되면 단가가 들어가므로 가격 미확인 경고가 뜨지 않는다.
- 대봉감은 주문에 크기가 없으면 후보가 동점이라 가격 미확인으로 남는다.
- 사전 키워드 `서귀포`, `타이벡`은 과일명이 아니어서 ‘서귀포 레드향’처럼 다른 과일과 함께 쓰이면 감귤로 판정될 수 있다. 현재까지 주문에는 이런 사례가 없다.
- 이미 배정된 작업건의 저장값은 자동으로 바뀌지 않는다.
- 2026-10-29 밤호박(신흥유통) 단가 누락 14건의 원인은 별도 확인이 필요하다.

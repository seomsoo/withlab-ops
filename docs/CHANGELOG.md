# 사용자 요청 및 변경 이력

사용자가 요청한 기능 추가·수정과 실제 반영 내용을 기록한다. 최신 날짜를 위에 추가하고, **요청 → 반영 내용 → 상태 → 확인 사항** 순서로 작성한다. 후속 작업은 완료 항목과 구분하며 구현·배포·검증 상태를 혼동하지 않는다.

## 2026-11-02 — 감귤 공급처 상품 매칭 수정

**요청:** 감귤을 뺵스팜에 보내는데 공급처 배정에서 업체 상품명이 아닌 플랫폼 상품명이 나와 수동으로 작업 중. 뺵스팜 상품목록은 중량·크기 조합 6개뿐인데도 매칭이 잘 되지 않음.

**원인:** 2026-09-16에 과일 사전 `감` 카테고리가 키워드 `감`으로 추가되면서 ‘감귤’에 `감`과 `감귤`이 동시에 잡혔다. 카테고리가 둘 이상이면 과일을 판별하지 않는 규칙 때문에 공급처 상품을 찾지 못했고, 발주 상품명이 플랫폼 상품명으로 대체되며 단가도 비었다. 감홍사과(`감`+`사과`), 대봉감(`감`+`대봉감`)도 같은 구조로 충돌했다.

**반영 내용**

| 구분 | 변경 |
| --- | --- |
| 과일 판별 | 같은 글자에 겹친 키워드는 긴 쪽, 길이가 같으면 뒤쪽을 남김 (예: 햇감귤 → 감귤) |
| 등급·크기 | 판정된 과일의 사전에서만 찾음 |
| 옵션 우선 | 중량·크기는 상품명보다 옵션을 먼저 봄. `[S-M 로얄과]`처럼 대괄호 안의 크기도 읽음 |
| 동점 처리 | 공급처 상품 후보가 최고점 동점이면 임의로 고르지 않고 플랫폼 상품명과 빈 단가로 둠. 가격 미확인으로 잡혀 작업자가 직접 선택 |
| 감귤 기본 크기 | 주문에 크기가 없으면 대과로 판단 (크기가 없는 주문 6,097건 중 작업자 선택 6,043건이 대과) |
| 운영 과일 사전 `감` | 키워드 `감` 삭제. `햇감`, `단감` 유지. 카테고리는 유지 |
| 운영 과일 사전 `감귤` | 크기 표현 `중대`, `혼합`, `m-l`, `l-2l`, `2l-l`, `로열`, `꼬마` 추가. 중량 변환 `2kg → 3kg`, `2.5kg → 3kg` 추가 |

**상태:** 운영 과일 사전 변경 완료. 코드는 `fix/gamgyul-attribute-matching` 브랜치에 있으며 **`main` 병합·배포 전**이다. 브라우저 화면 확인은 하지 않았다.

**검증 결과(운영 데이터로 재현, 실제 주문 처리 결과 아님):** 과일 인식은 전체 12,618건 중 4,628건에서 12,524건으로 늘었다. 최근 3주 귤 221종은 품목 검토에서 뺵스팜을 지정하면 모두 상품명과 단가가 들어간다(수정 전 0종). 작업자가 선택한 상품과 중량·크기가 일치하는 비율은 7,279건 중 7,245건(99.5%)이다. 현재 공급처 상품목록에 있는 상품으로 저장된 10,575건을 수정 전후로 비교하면 저장값과 같은 상품을 고른 수가 2,852건에서 10,490건으로 늘었고, 맞던 주문이 틀어진 경우는 없었다. 나머지 85건 중 71건은 단가 없음으로 표시되고 14건은 다른 상품이 선택된다.

**확인 사항**

- 품목 검토 없이 자동 배정하면 귤 221종 중 154종은 추천 상태로 남는다.
- 위 14건처럼 저장값과 다른 상품이 선택되면 단가가 들어가므로 가격 미확인 경고가 뜨지 않는다.
- 대봉감은 주문에 크기가 없으면 후보가 동점이라 가격 미확인으로 남는다.
- 사전 키워드 `서귀포`, `타이벡`은 과일명이 아니어서 ‘서귀포 레드향’처럼 다른 과일과 함께 쓰이면 감귤로 판정될 수 있다. 현재까지 주문에는 이런 사례가 없다.
- 이미 배정된 작업건의 저장값은 자동으로 바뀌지 않는다.
- 2026-10-29 밤호박(신흥유통) 단가 누락 14건의 원인은 별도 확인이 필요하다.

## 2026-11-02 — 공급처 배정 가격 미확인 표시

**요청:** 공급처는 배정됐는데 가격 미확인으로 나오는 건을 확인하고 넘어갈 수 있게 표시해 달라.

**반영 내용**

- 공급처 배정 화면에 가격 미확인 경고 배너와 필터를 추가한다.
- 해당 품목 행에 뱃지를 표시하고, 툴팁으로 사유(상품 목록 없음, 상품 매칭 실패, 목록에 가격 없음, 배정에 가격 미반영)를 보여 준다.
- ‘다음: 발주서 다운로드’를 누르면 확인창에서 ‘확인하러 가기’와 ‘그대로 진행’을 선택한다. 진행을 막지는 않는다.
- 공급처가 없는 미분류·추천 품목이 가격 미확인 건수에 포함되던 문제를 수정한다.
- 예상 발주금액을 품목의 첫 주문 단가가 아닌 주문별 단가로 합산한다.

**상태:** 코드는 `fix/gamgyul-attribute-matching` 브랜치에 있으며 **커밋·배포 전**이다. 관련 테스트는 통과했고, 브라우저 화면 확인은 하지 않았다.

**확인 사항:** 배정 화면의 ‘건’은 품목 그룹 수, 다운로드 화면의 ‘건’은 주문 라인 수라서 숫자가 다를 수 있다. 상품 목록을 갱신해도 기존 배정의 단가는 자동으로 바뀌지 않는다.

## 2026-11-02 — 음수 마진 빨간 글씨 표시

**요청:** 가격정리 엑셀에서 마진금액이 마이너스면 빨간 글씨로 표시.

**반영 내용:** 마진금액(P열)의 실제 데이터 영역에 조건부 서식을 추가한다. 숫자가 0보다 작을 때만 글씨를 빨간색으로 표시하며, 0·양수·빈칸은 기존 표시를 유지한다. 수식 또는 금액을 수정해 마진이 바뀌면 Excel이 색상을 다시 판단한다. 계산 수식·통화 표시·배경색은 변경하지 않는다.

**상태:** 출력 코드 반영. 기존 다운로드 파일에는 소급 적용되지 않으므로 다시 다운로드해야 한다. 자동 검증으로 조건부 서식 규칙과 기존 수식·스타일 보존을 확인하며, Excel 화면에서의 색상 검증은 별도 확인이 필요하다.

## 2026-11-02 — 가격정리 택배사 출력 변경

**요청:** 최초 가격정리 파일에는 원본 택배사를 가져오지 않아도 됨.

**반영 내용**

- 쿠팡·토스 모두 가격정리 엑셀의 택배사(A열)를 빈칸으로 출력한다.
- 택배사 열과 서식은 유지한다.
- 송장번호(B열)는 기존대로 업로드 원본에 값이 있으면 가져온다. 이후 매칭된 운송장을 가져오는 기능은 아직 포함하지 않는다.

**상태:** 코드 반영 완료. 관련 테스트 통과.

**확인 사항:** 주문일자를 더블클릭한 뒤 `####`로 보이는 현상은 기존 날짜·시간 서식 대비 열 너비가 좁아 발생할 수 있다. 사용자가 열 너비 조절로 대응하기로 하여 이번에는 날짜 서식·열 너비를 변경하지 않았다.

### 사용 중 발견한 오류와 수정

- **최초 파일명 열 조회 실패:** 화면에서 사용하는 `original_file_name` 열이 DB에 없어 발생. 연결된 DB에 마이그레이션과 최초 파일명 보존 트리거 적용, 기존 파일명 이관 및 공통 양식 등록 완료.
- **배정 응답 형식 오류:** 주문별 배정이 배열이 아닌 단일 객체로 반환되는 경우를 누락. 객체·배열·미배정 null을 공통 형식으로 변환하도록 수정하고 회귀 테스트 추가.
- **일부 배정 경로에서 단가 누락:** 상품명 매핑이 적용된 공급처 변경·수동 배정·분배 경로에서도 식별된 상품의 단가를 저장하도록 보완.

**상태:** 기능 구현 및 DB·Storage 설정 완료. 사용자가 결과 파일 다운로드 확인. 커밋·푸시와 서비스 배포 성공 여부는 Git/배포 이력에서 별도로 확인한다.

**검증:** 2026-11-02 기준 자동 테스트 283개, 타입 검사, 린트 통과. 생성 파일의 A~M 입력, 나머지 셀·수식 보존 및 3,800건 출력을 자동 검증했다. 실제 주문 전체 금액 대조 및 Excel 자체 재계산 검증을 모두 완료한 것은 아니다.

**제한:** 기존 정산 수식은 3,107행까지다. 3,105건을 초과하면 안내하며, A~M의 전체 주문은 출력하되 정산 수식을 자동 확장하지 않는다.

## 후속 작업 — 운송장 매칭 후 가격정리 재다운로드

**요청:** 발주 직후 가격정리는 먼저 받고, 나중에 운송장번호도 결과에 포함하고 싶음.

**상태:** 논의만 진행. 이번 구현에서 제외.

**논의한 방향:** 운송장 매칭 후 해당 주문의 택배사·송장번호를 넣어 가격정리 파일을 다시 다운로드한다. 기존 구매가격은 유지한다.

**다음 작업에서 확인할 사항:** 최초 파일을 사용자가 직접 편집하는지, 재다운로드 위치, 택배사 표기 기준, 일부 운송장만 매칭된 상태의 처리 방식. 로컬 엑셀 파일을 자동으로 갱신하는 기능으로 합의한 것은 아니다.
